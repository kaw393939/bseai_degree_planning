Curriculum Design
Students should be able to:
1) Software engineering for AI systems
Build production-quality services (APIs, data pipelines, model/LLM-backed endpoints), not just notebooks(IS 218, IS 421, IS 425)
Use Git, testing, CI, code review, packaging, and debugging as defaults (IS 218, IS 390, IS 425)
Design for performance, reliability, and maintainability (modularity, logging, observability) (IS 390, IS 455, IS 425)
2) Data competence (the real bottleneck)
Use SQL fluently; model data cleanly; understand schemas, joins, ETL/ELT, and data quality checks (IS 331, IS 465)
Graph Database and Graph Analysis (IS 331)
Create datasets responsibly (labeling plans, leakage prevention, sampling bias awareness) (IS 465, IS 392)
Work with unstructured enterprise data (docs, tickets, PDFs, email-like text) and metadata (IS 392, IS 480)
3) Core ML foundations (enough to be dangerous—in a good way)
Frame problems (classification/regression/ranking/clustering) and choose baselines(IS 465)
Evaluate properly (train/val/test discipline, leakage checks, metrics selection, error analysis)(IS 465, IS 480)
Explain tradeoffs (bias/variance, overfitting, calibration, interpretability basics) (IS 480)
4) Generative AI / LLM application engineering
Build RAG-style and tool-using LLM apps (retrieval, chunking, embeddings, reranking, tool calls)(IS 392, IS 425)
Do prompt design and prompt robustness (structured outputs, guardrails, fallback behavior)(IS 392, IS 425)
Decide when to use RAG vs fine-tuning vs classical ML vs rules(IS 480, IS 465)
5) Evaluation, reliability, and “AI QA”
Build evaluation harnesses (offline test sets, golden answers, scenario suites, regression tests)(IS 480, IS 425)
Measure and reduce hallucinations / ungrounded outputs and know that metrics can be fragile(IS 392, IS 480)
Use human-in-the-loop review appropriately and document limitations(IS 375, IS 448)

6) Responsible AI + governance literacy
Apply risk-based thinking: map context, identify harms, define controls, document decisions(IS 350)
Produce practical artifacts: model cards/system cards, data documentation, eval reports, incident playbooks(IS 390, IS 425)
Communicate compliance implications (especially in regulated settings)(IS 455, IS 350)
7) Business + product ability (how AI creates value)
Translate stakeholder needs into measurable requirements and acceptance tests (IS 390)
Estimate cost/latency/benefit; choose “good enough” solutions that scale in real orgs(IS 455, IS 425)
Communicate risks, limitations, and rollout strategy to non-technical audiences(IS 390, IS 375)
8) Collaboration and communication (what makes juniors stand out)
Write clear technical docs and runbooks; present tradeoffs; defend choices with evidence(IS 390, IS 491)
Work in teams with agile-ish execution, project planning, and ownership behaviors(IS 491, IS 218)
