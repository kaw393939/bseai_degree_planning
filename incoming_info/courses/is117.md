## Course Description

This course is a small-cohort studio that boots students from “zero” to a functional baseline for building and presenting simple web products. Students learn (1) essential professional tooling (Linux/terminal file management, VS Code, Git/GitHub, and deployment), (2) web fundamentals (HTML/CSS/JavaScript at a conceptual and practical starter level), and (3) the vocabulary and mental models required to make and critique products (asking good questions, usability basics, design history/movements, persuasion basics, and brand archetypes).

The course is intentionally "whole person" and portfolio-oriented: students leave with two published artifacts:

1) a museum-style single-topic website (design/psychology/technology theme of the student’s choice)
2) a personal portfolio site they can continue to evolve across the degree

Technical skill building is required, but the course emphasizes conceptual frameworks and vocabulary to help students reason about products and communicate professionally.

## Course Learning Outcomes (Measurable)

By the end of the course, students will be able to:

1) Use a professional workflow to build and publish a simple product: navigate a filesystem in the terminal, work in VS Code, use Git/GitHub, and deploy a static site.
2) Build and iterate on a simple web product using HTML/CSS/JavaScript fundamentals and a clear information architecture.
3) Ask better questions using course frameworks (e.g., 5 Whys, hypothesis-first thinking, and structured prompts) to clarify requirements and improve outcomes.
4) Apply basic usability checks (clarity, navigation, accessibility basics) and provide evidence of improvements (e.g., checklists, simple user test notes, Lighthouse snapshots).
5) Communicate professional identity by producing and presenting a portfolio and a museum-style website with clear attribution and an AI-use note.

Checklist-based demonstrations of:

- terminal navigation and file management
- VS Code setup and project execution

Weekly Labs (15%)
Checklist-based technical submissions (terminal tasks, Git workflow steps, deployment checkpoints, basic QA evidence).
Portfolio Website (25%)

Museum Website (35%)
A museum-style website organized as a “digital exhibit” around a theme the student chooses (design movement, psychology of design, or technology history). Includes citations, a clear information architecture, and a short “what I learned” reflection.

## Responsible Use of Artificial Intelligence (Aligned to NJIT)

AI can be a valuable learning aid, but students must follow instructor rules for each assignment and uphold academic integrity. If AI use is not explicitly authorized for an assignment, submitting AI-generated work may constitute a violation.

Course expectations:

Students must ensure submitted work is original and properly attributed, including AI tools and external sources.
Students must critically evaluate and understand AI-assisted output; “the AI wrote it” is not acceptable.
