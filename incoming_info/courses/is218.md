## Course Description

This course is the third studio in the BS in Enterprise AI spine. Students move from client-side interactivity (IS 118) to building, testing, deploying, and maintaining **full-stack web applications** — front-end, API, and persistence layer working together as a production system.

The defining question of this studio: **"Is it correct?"** Copilot can generate fifty lines of code. Is it secure? Maintainable? Does it handle edge cases? Professional Judgment is the ability to evaluate output — human or machine-generated — and make a defensible decision about whether to ship it.

Students learn to:

1. Design and build a full-stack application with front-end, API, and database layers
2. Write and run automated tests (unit, integration, end-to-end basics)
3. Set up CI/CD pipelines that catch regressions before deployment
4. Deploy to a production-like environment with logging and basic monitoring
5. Use AI coding assistants critically — accepting, rejecting, and modifying suggestions with documented reasoning

The course uses **The Pragmatic Programmer** (Thomas & Hunt) as its spine book, providing frameworks for engineering judgment that transfer beyond any single language or framework.

By the end of this studio, students have shipped a working, tested, deployed application — and can explain every decision they made along the way.

## Course Learning Outcomes (Measurable)

By the end of the course, students will be able to:

1. **Design** a full-stack application architecture with clearly separated front-end, API, and persistence layers, justifying technology choices with tradeoff analysis.
2. **Implement** a working web application with user authentication, CRUD operations, input validation, and error handling using professional coding standards.
3. **Write** automated tests (unit and integration) that verify functional correctness, and explain the reasoning behind test case selection.
4. **Configure** a CI/CD pipeline (GitHub Actions) that runs tests on every push, blocks merges on failure, and deploys passing builds automatically.
5. **Deploy** an application to a production-like environment with environment variable management, structured logging, and basic health monitoring.
6. **Evaluate** AI-generated code critically — accepting, rejecting, or modifying suggestions — and document the reasoning in an AI audit log.
7. **Conduct** a code review using a structured rubric, identifying issues in correctness, security, readability, and maintainability.
8. **Present** a working system at Demo Day with a live demonstration, architecture walkthrough, and honest assessment of limitations.

## Assessment Categories and Descriptions

**Studio Checkoffs (10%)**
Checklist-based demonstrations of:

- Full-stack project scaffolding (front-end + API + DB)
- Automated test suite setup and execution
- CI/CD pipeline configuration (GitHub Actions)
- Production deployment with environment variables and logging

**Weekly Labs & Code Reviews (15%)**
Technical submissions including: API endpoint implementation, database schema design, test writing exercises, and structured code reviews of peer work. Each lab builds toward the final project.

**Midterm Project Checkpoint (15%)**
A working partial application demonstrating: user authentication, at least two functional routes/endpoints, database persistence, and a passing test suite. Accompanied by an architecture document explaining design decisions.

**Final Project: Full-Stack Application (30%)**
A complete, tested, deployed web application with:

- User authentication and authorization
- CRUD operations with validated input
- Automated test suite (unit + integration; minimum coverage targets defined per section)
- CI/CD pipeline with automated deployment
- Structured logging and basic monitoring/health check
- README, deployment runbook, and changelog
- Clean commit history demonstrating iterative development

**AI Audit Log — Human Edge Artifact (15%)**
A structured document maintained throughout the semester recording:

- Every significant AI-assisted code suggestion accepted, rejected, or modified
- The student's reasoning for each decision
- Patterns observed: where AI was helpful, where it was wrong, where it was dangerous
- A final reflection: "What I've learned about when to trust and when to override"

This is the Professional Judgment artifact — evidence that the student can evaluate machine output, not just consume it.

**Demo Day Presentation (15%)**
A live demonstration to peers and (where possible) industry judges:

- Working application walkthrough
- Architecture explanation (why these technologies, why this structure)
- Testing strategy and CI/CD pipeline demonstration
- Honest assessment of limitations and what would change in v2
- Scored on: functionality, engineering quality, communication clarity, and candor

## Responsible Use of Artificial Intelligence (Aligned to NJIT)

AI is a core tool in this course — students are expected to use AI coding assistants (Copilot, ChatGPT, etc.) as part of their workflow. However, the purpose is to develop **judgment about AI output**, not dependence on it.

Course expectations:

- Students must ensure submitted work is original and properly attributed, including AI tools and external sources.
- Students must critically evaluate and understand AI-assisted output; "the AI wrote it" is not acceptable.
- Students must comply with copyright and citation expectations.
- **The AI Audit Log is required** — it documents what AI was used for, what was changed by the student, what was verified, and why.

The goal is not to avoid AI but to use it like a professional: critically, selectively, and with accountability.
