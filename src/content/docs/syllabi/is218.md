# IS 218 — Building Web Applications

**Studio label:** Software Engineering
**Credits:** 3 | **Contact hours:** 3 hrs/week | **Mode:** Studio (face-to-face)
**Human Edge capability:** Professional Judgment
**40/60 split:** Manual testing and review / AI-directed full-stack development
**Prerequisites:** IS 118 and CS 100

<Aside type="tip" title="Position in the spine">
This is **Studio 3** — where students transition from building pages and interactive features to engineering **production systems**. The defining shift: you're now responsible for code that other people depend on.
</Aside>

---

## Course Description

Students move from client-side interactivity (IS 118) to building, testing, deploying, and maintaining **full-stack web applications** — front-end, API, and persistence layer working together as a production system.

The defining question of this studio: **"Is it correct?"**

Copilot can generate fifty lines of code. Is it secure? Maintainable? Does it handle edge cases? Professional Judgment is the ability to evaluate output — human or machine-generated — and make a defensible decision about whether to ship it.

Students learn to design full-stack architectures, write automated tests, configure CI/CD pipelines, deploy with observability, and use AI coding assistants critically — accepting, rejecting, and modifying suggestions with documented reasoning.

By the end of this studio, students have shipped a working, tested, deployed application — and can explain every decision they made along the way.

---

## Why Professional Judgment?

AI can generate code faster than any human. It cannot decide whether to ship it.

Professional Judgment is the capacity to evaluate work — your own or the machine's — against standards of correctness, security, maintainability, and fitness for purpose. It requires understanding consequences: what happens when this code runs at scale, handles real user input, or fails at 3 AM. This is irreducibly human because it involves **stakes** — caring about outcomes beyond the immediate output.

---

## Course Learning Outcomes

By the end of this course, students will be able to:

1. **Design** a full-stack application architecture with clearly separated front-end, API, and persistence layers, justifying technology choices with tradeoff analysis (Create)
2. **Implement** a working web application with user authentication, CRUD operations, input validation, and error handling (Create)
3. **Write** automated tests (unit and integration) that verify functional correctness, and explain test case selection reasoning (Create)
4. **Configure** a CI/CD pipeline (GitHub Actions) that runs tests on every push, blocks merges on failure, and deploys passing builds (Apply)
5. **Deploy** an application to a production-like environment with environment variable management, structured logging, and health monitoring (Apply)
6. **Evaluate** AI-generated code critically — accepting, rejecting, or modifying suggestions — and document reasoning in an AI Audit Log (Evaluate)
7. **Conduct** a code review using a structured rubric, identifying issues in correctness, security, readability, and maintainability (Analyze)
8. **Present** a working system at Demo Day with live demonstration, architecture walkthrough, and honest assessment of limitations (Create)

## Key Deliverables

### Full-Stack Application (30%)
A complete, tested, deployed web application with:
- User authentication and authorization
- CRUD operations with validated input
- Automated test suite (unit + integration)
- CI/CD pipeline with automated deployment
- Structured logging and health check
- README, deployment runbook, and changelog
- Clean commit history demonstrating iterative development

### AI Audit Log — Human Edge Artifact (15%)
A structured document maintained throughout the semester recording:
- Every significant AI-assisted code suggestion accepted, rejected, or modified
- The student's reasoning for each decision
- Patterns observed: where AI was helpful, where it was wrong, where it was dangerous
- A final reflection: *"What I've learned about when to trust and when to override"*

This is the Professional Judgment artifact — evidence that the student can evaluate machine output, not just consume it.

### Demo Day Presentation (15%)
A live demonstration including: working application walkthrough, architecture explanation, testing strategy, CI/CD pipeline demonstration, and honest assessment of limitations. Scored on functionality, engineering quality, communication clarity, and candor.

## The 40/60 Split in Practice

In a typical 2-hour lab block (75 min lecture + 45 min lab):

| Phase | Time | Activity |
|-------|------|----------|
| Hard-Way | 40 min | Write a test by hand → run it → watch it fail → implement the feature manually → watch it pass |
| Agentic | 60 min | Direct Copilot to build *three more features* using the pattern you just learned. Audit each suggestion. Log decisions. |

The hard-way phase builds understanding; the agentic phase builds velocity. Neither works alone.
