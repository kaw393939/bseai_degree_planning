## Course Description

This studio teaches students to think about data as a **theory about the world** — not just a collection of rows and columns.

Students learn relational database design (normalization, SQL fluency, schema evolution), then extend into the data structures that power modern AI: graph databases for representing relationships, vector embeddings for representing semantic similarity, and hybrid retrieval systems that combine multiple access patterns.

The defining question: **"What does this data capture — and what does it miss?"**

Every database schema is an editorial decision about what matters. Every vector embedding is a lossy compression. Every knowledge graph reflects someone's choices about which relationships to encode. Students learn to build with all of these — and to document the assumptions, distortions, and blind spots built into their data representations.

---

## Why Epistemic Humility?

AI can process more data than any human. It cannot recognize that the data itself is wrong, biased, or missing the point entirely.

Epistemic Humility is the capacity to stand outside your own representations — to see a schema, an embedding, or a knowledge graph not as truth but as a *model* of truth with specific limitations. This is irreducibly human because it requires **meta-cognition**: thinking about your own thinking, questioning your own assumptions, and acknowledging what you don't know.

## Course Learning Outcomes

By the end of this course, students will be able to:

1. **Design** relational database schemas that model real-world domains with appropriate normalization (Create)
2. **Write** SQL queries including joins, aggregations, subqueries, and window functions (Apply)
3. **Build** data pipelines with validation, quality checks, and error handling (Create)
4. **Explain** graph databases and knowledge graphs as data structures for representing relationships (Understand)
5. **Explain** vector embeddings as data structures for representing semantic similarity (Understand)
6. **Implement** hybrid retrieval combining metadata filtering, semantic search, and optionally graph traversal (Create)
7. **Document** data assumptions — what a dataset captures, what it distorts, and what's missing (Evaluate)
8. **Compare** data structures (B-trees, hash maps, graphs, vectors) as *theories* about what matters (Analyze)
9. **Apply** data quality principles including reproducibility, validation, and governance (Apply)
10. **Construct** data-aware Context Packs that explicitly address epistemic limitations (Create)

## Key Deliverables

### Hybrid Retrieval System (25%)
A working system that combines multiple data access patterns:
- Relational database with proper schema, constraints, and indexes
- Knowledge graph representing domain entities and relationships
- Vector embeddings for semantic search
- Hybrid query pipeline: metadata filtering → semantic ranking → optional graph traversal
- Data quality validation at each stage
- Documentation: schema decisions, data pipeline architecture, quality metrics

### Data Assumptions Document — Human Edge Artifact (15%)
A structured document analyzing:
- What the student's data **captures**: entities, relationships, attributes, and their scope
- What it **distorts**: normalization tradeoffs, embedding compression, graph simplification
- What it **misses entirely**: perspectives not represented, relationships not encoded, data not collected
- How they would **detect** if their assumptions were wrong
- What they would **change** given unlimited resources

This is the Epistemic Humility artifact — evidence that the student can reason about the limits of their own data representations.

### Demo Day Presentation (15%)
Live demonstration of the hybrid retrieval system with walkthrough of data architecture, retrieval pipeline, and honest assessment of data quality limitations.

## The Data Structures as Theories

A central framework in this course: every data structure is a *theory* about what matters.

| Data Structure | Theory | What It's Good At | What It Misses |
|---------------|--------|-------------------|----------------|
| **B-tree (relational)** | Exact values and ranges matter | Fast lookup, range queries, ACID | Semantic similarity, fluid relationships |
| **Hash map** | Direct access by key matters | O(1) lookup | Ordering, ranges, relationships |
| **Graph** | Relationships between entities matter | Path finding, pattern matching, connected queries | Scale at dense connections, numeric aggregation |
| **Vector embedding** | Semantic similarity matters | "Find things like this", fuzzy matching | Precision, explainability, edge cases |

None is universally better. The choice depends on what questions you need to answer — and the Data Assumptions Document forces students to articulate those choices explicitly.
