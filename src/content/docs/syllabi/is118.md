# IS 118 — Interactive Web Development

**Credits:** 3 | **Contact hours:** 3 hrs/week | **Mode:** Studio (face-to-face)
**Human Edge capability:** Translation
**40/60 split:** Manual JavaScript / AI-directed app building
**Prerequisites:** IS 117

<Aside type="caution" title="Proposed course">
IS 118 is a **new course proposal**, not in the current NJIT catalog. It requires a full new-course proposal through faculty governance. The course fills a critical gap between IS 117 (static sites) and IS 218 (full-stack applications).
</Aside>

---

## Course Description

This studio bridges the gap between a page and an application — between displaying information and enabling interaction. Students learn JavaScript fundamentals, DOM manipulation, API integration, debugging workflows, and security hygiene. The course builds on IS 117's web foundations and prepares students for the full-stack engineering of IS 218.

The defining question of this studio: **"Can you make the invisible visible?"**

Every AI product is an act of translation — taking data, logic, or a model's reasoning and turning it into something humans can interact with, understand, and act on. Students practice this by building interactive applications that make complex information tangible for specific audiences.

Students leave with a deployed interactive web application, a Translation Brief explaining their design decisions, and the beginning of real debugging intuition.

---

## Why Translation?

AI can generate interfaces. It cannot decide what another person needs to understand.

Translation requires a **theory of mind** — understanding what the audience doesn't know and meeting them there. It requires empathy: seeing the invisible concept through someone else's eyes and choosing the representation that makes it click. This is irreducibly human because it demands modeling another consciousness.

---

## Course Learning Outcomes

By the end of this course, students will be able to:

1. **Write** JavaScript programs that manipulate the DOM, handle events, and manage state (Create)
2. **Integrate** external APIs into web applications, handling authentication, errors, and data formats (Apply)
3. **Debug** client-side applications using browser developer tools and systematic approaches (Analyze)
4. **Implement** form validation, data handling, and basic security hygiene (Apply)
5. **Design** interactive interfaces that make invisible concepts tangible for specific audiences (Create)
6. **Write** a Translation Brief explaining what invisible thing the app makes visible and how (Evaluate)
7. **Construct** Context Packs that include API documentation and interaction requirements (Apply)
8. **Compare** human-only vs. AI-assisted development approaches, documenting tradeoffs (Evaluate)
9. **Create** technical documentation (README, setup guide, test checklist) for a non-technical audience (Create)

## Key Deliverables

### Interactive Web Application (25%)
A deployed interactive application with at least one API integration, client-side state management, form handling, and error handling. The app must make something invisible (data, a process, a concept) visible and interactive for a specific audience.

### Translation Brief — Human Edge Artifact (15%)
A structured document explaining:
- What invisible thing does this application make visible?
- Who is the target audience and what do they not currently understand?
- What design decisions make the concept tangible?
- What was lost or simplified in translation, and why?

This is the Translation artifact — evidence that the student can think about **audience** and **comprehension**, not just functionality.

### Demo Day Presentation (15%)
Live demonstration to peers showing the working application, the translation rationale, and honest assessment of what works and what doesn't.

## Justification for New Course

The current NJIT catalog has no course between IS 117 (static web development) and IS 218 (full-stack applications). This gap forces IS 218 to teach JavaScript fundamentals *and* full-stack architecture simultaneously — too much cognitive load for a single course.

IS 118 absorbs the client-side JavaScript content currently crammed into IS 219 and creates a proper developmental bridge. Students enter IS 218 already fluent in JavaScript, API integration, and debugging.
