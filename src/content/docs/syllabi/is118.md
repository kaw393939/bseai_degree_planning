# IS 118 — Full-Stack Web Applications

**Credits:** 3 | **Contact hours:** 3 hrs/week | **Mode:** Studio (face-to-face)
**Human Edge capability:** Professional Judgment
**40/60 split:** Manual testing and review / AI-directed full-stack development

## Course Description

They learn JavaScript fundamentals, API design, database integration, automated testing, CI/CD pipelines, and AI-assisted development.

The defining question of this studio: **"Is it correct?"**

AI can generate fifty lines of code in seconds. Is it secure? Maintainable? Does it handle edge cases? Professional Judgment is the ability to evaluate output — human or machine-generated — and make a defensible decision about whether to ship it.

Students learn to design full-stack architectures, write automated tests, configure CI/CD pipelines, deploy with observability, and use AI coding assistants critically — accepting, rejecting, and modifying suggestions with documented reasoning.

By the end of this studio, students have shipped a working, tested, deployed application — and can explain every decision they made along the way.

---

## Why Professional Judgment?

AI can generate code faster than any human. It cannot decide whether to ship it.

Professional Judgment is the capacity to evaluate work — your own or the machine's — against standards of correctness, security, maintainability, and fitness for purpose. It requires understanding consequences: what happens when this code runs at scale, handles real user input, or fails at 3 AM. This is irreducibly human because it involves **stakes** — caring about outcomes beyond the immediate output.

## Course Learning Outcomes

By the end of this course, students will be able to:

1. **Write** JavaScript programs that manipulate the DOM, handle events, call APIs, and manage state (Create)
2. **Design** a full-stack application architecture with clearly separated front-end, API, and persistence layers, justifying technology choices (Create)
3. **Implement** a working web application with user authentication, CRUD operations, input validation, and error handling (Create)
4. **Write** automated tests (unit and integration) that verify functional correctness, and explain test case selection reasoning (Create)
5. **Configure** a CI/CD pipeline (GitHub Actions) that runs tests on every push, blocks merges on failure, and deploys passing builds (Apply)
6. **Deploy** an application to a production-like environment with environment variable management and health monitoring (Apply)
7. **Evaluate** AI-generated code critically — accepting, rejecting, or modifying suggestions — and document reasoning in an AI Audit Log (Evaluate)
8. **Conduct** a code review using a structured rubric, identifying issues in correctness, security, readability, and maintainability (Analyze)
9. **Present** a working system at Demo Day with live demonstration, architecture walkthrough, and honest assessment of limitations (Create)

## Key Deliverables

### Full-Stack Application (30%)
A complete, tested, deployed web application with:
- User authentication and authorization
- CRUD operations with validated input
- Automated test suite (unit + integration)
- CI/CD pipeline with automated deployment
- Health check endpoint
- README, deployment runbook, and changelog
- Clean commit history demonstrating iterative development

### AI Audit Log — Human Edge Artifact (15%)
A structured document maintained throughout the semester recording:
- Every significant AI-assisted code suggestion accepted, rejected, or modified
- The student's reasoning for each decision
- Patterns observed: where AI was helpful, where it was wrong, where it was dangerous
- A final reflection: *"What I have learned about when to trust and when to override"*

This is the Professional Judgment artifact — evidence that the student can evaluate machine output, not just consume it.

### Demo Day Presentation (15%)
A live demonstration including: working application walkthrough, architecture explanation, testing strategy, CI/CD pipeline demonstration, and honest assessment of limitations. Scored on functionality, engineering quality, communication clarity, and candor.

## The 40/60 Split in Practice

| Component | Hard-Way (40%) | Agentic (60%) |
|-----------|---------------|---------------|
| JavaScript | Write core logic by hand; manual DOM manipulation | AI-assisted feature development; rapid prototyping |
| API design | Build endpoints manually; handle errors by hand | AI-directed API scaffolding; boilerplate generation |
| Testing | Write first test manually; understand what it proves | AI-assisted test generation; coverage expansion |
| Deployment | Configure CI/CD step by step; understand the pipeline | AI-directed infrastructure-as-code; rapid config |

The hard-way phase builds understanding; the agentic phase builds velocity. Neither works alone.
