# The Context Pack

> *In the old paradigm, the meta-skill was studying — absorbing and retaining information. In the new paradigm, the meta-skill is context management — assembling and transferring the right information to AI agents so they can work effectively on your behalf.*

---

## What It Is

The Context Pack is a structured document that students create for every major project in every studio course. It is the briefing material that enables effective AI agent work — the operational artifact behind "CEO of agents."

Every Context Pack contains four components:

| Component | Contents | Purpose |
|---|---|---|
| **Project Brief** | Problem statement, constraints, success criteria, scope boundaries | Tell the agent *what* to do and *when to stop* |
| **Domain Context** | Key concepts, terminology, relationships, prior work, relevant standards | Give the agent enough domain knowledge to produce relevant output |
| **Evaluation Criteria** | How to judge whether output is good — acceptance tests, quality metrics, style guidelines | Enable the human to exercise informed judgment |
| **Prior Context** | What's been tried, what worked, what failed, lessons from previous iterations | Prevent the agent from repeating known mistakes |

---

## Why It Matters

### For Students
The Context Pack is the most transferable skill in the degree. Regardless of what tool, framework, or AI model exists in 2030, the ability to:
- Clearly define a problem and its constraints
- Assemble relevant domain knowledge
- Specify evaluation criteria
- Document prior context and lessons learned

...is the skill that makes someone an effective AI director in any domain.

### For Employers
Every job posting in our [evidence base](/bseai_degree_planning/evidence/job-market/) describes some version of context management:

- **Morningstar ($145–183K):** "Capture technical learnings and provide handoff documentation for production teams"
- **OpenAI ($137–250K):** "Safe and effective deployment" — which requires thorough context about the deployment environment
- **WorkWhile:** "Build, ship and iterate on LLM-backed agentic workflows" — iteration requires context about what's been tried

### For Accreditation
The Context Pack satisfies ABET's documentation and communication outcomes while simultaneously teaching the program's core operational skill. It is assessed, graded, and accumulated.

## How It Evolves Across the Spine

The Context Pack starts simple and becomes sophisticated as students develop capabilities:

### Year 1: Foundations

**IS 117 — First Context Pack**
```
Project Brief: Build a museum-style website about [topic]
Domain Context: HTML structure, CSS layout principles, target audience
Evaluation Criteria: Valid HTML, responsive layout, accessible navigation
Prior Context: N/A (first project)
```
*Learning goal:* Students practice defining a problem and specifying what "done" means.

**IS 118 — Interactive Context Pack**
```
Project Brief: Build interactive app that makes [invisible thing] visible
Domain Context: JavaScript patterns, API documentation, data format specs
Evaluation Criteria: Functional interactive features, error handling, UX quality
Prior Context: Portfolio site from IS 117, lessons from first Context Pack
```
*Learning goal:* Students practice giving domain context that enables better AI output.

### Year 2: Professional Context

**IS 218 — Engineering Context Pack**
```
Project Brief: Full-stack app with [specific user need]
Domain Context: Architecture patterns, testing frameworks, CI/CD requirements
Evaluation Criteria: Test coverage, deployment success, code review checklist
Prior Context: IS 117/118 projects, known pitfalls, architectural decisions made
```
*Learning goal:* Context Pack includes technical architecture context and testing criteria.

**IS 265 — Organizational Context Pack**
```
Project Brief: Solve [stakeholder's stated problem] — but first find the real one
Domain Context: Stakeholder interview notes, organizational dynamics, requirements
Evaluation Criteria: Did we solve the RIGHT problem? Stakeholder satisfaction?
Prior Context: Initial assumptions vs. discovered reality (tracked in Assumptions Log)
```
*Learning goal:* Context Pack includes human/organizational context, not just technical.

### Year 3: Deep Technical Context

**IS 219 — Infrastructure Context Pack**
```
Project Brief: Containerized service with [SLA requirements]
Domain Context: Infrastructure constraints, security requirements, failure modes
Evaluation Criteria: Uptime, recovery time, observability coverage, security posture
Prior Context: Failure Mode Analysis, prior incident data, known vulnerabilities
```
*Learning goal:* Context Pack includes failure modes and recovery requirements.

**IS 331 — Data Context Pack**
```
Project Brief: Data pipeline + retrieval system for [domain]
Domain Context: Schema design rationale, data quality assumptions, what's MISSING
Evaluation Criteria: Query performance, data quality metrics, retrieval relevance
Prior Context: Data assumptions document, known biases, representation choices
```
*Learning goal:* Context Pack explicitly addresses epistemic limitations — what the data doesn't capture.

### Year 4: Capstone Context

**IS 390 — Systems Context Pack**
```
Project Brief: Requirements + architecture for AI system solving [problem]
Domain Context: Full system architecture, component interactions, tradeoffs
Evaluation Criteria: Requirements traceability, architecture fitness, evaluation plan
Prior Context: Stakeholder analysis, competing designs, prior system analysis
```

**IS 425 — Production Context Pack**
```
Project Brief: Production AI system for [real client] with KG + HITL + evals
Domain Context: Client requirements, domain knowledge graph, existing systems
Evaluation Criteria: Production readiness, evaluation harness results, client satisfaction
Prior Context: All prior Context Packs synthesized, lessons from every studio
```
*Learning goal:* The capstone Context Pack is a professional-grade project brief.

## Assessment

The Context Pack is assessed on:

| Criterion | Weight | What It Measures |
|---|---|---|
| **Completeness** | 25% | Are all four components present and substantive? |
| **Specificity** | 25% | Is the context specific enough to enable good agent output? |
| **Evaluation criteria quality** | 25% | Would these criteria actually catch bad output? |
| **Evolution** | 25% | Does this Context Pack show growth from the previous one? |

Faculty review Context Packs both as standalone documents and as a progression across a student's portfolio.

## The Transferable Skill

A graduate who has built 8 Context Packs across 8 different domains can walk into any organization and say:

"Give me the problem. I'll construct the context, direct the agents, evaluate the output, and take responsibility for the result."

That's the "CEO of agents" — and the Context Pack is their primary tool.
