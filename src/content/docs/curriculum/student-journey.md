# Student Journey (Realistic)

This is the intended journey for an 18-year-old entering the BS in Enterprise AI and graduating with practical, employable engineering capability.

The philosophy is simple:

- Students learn by building.
- They build at “human speed” using terminal + Linux habits.
- They also learn how to wield AI tools responsibly.

## What “job-ready” means (minimum bar)

By graduation, a student should be able to sit down in a company environment and:

- Navigate a Linux environment, run software, read logs, and debug basic issues.
- Use Git professionally (branches, commits, PRs) and follow a CI workflow.
- Build and deploy a small service and maintain it (monitoring basics, rollback).
- Build an LLM-backed feature with evaluation evidence and safe failure modes.
- Communicate clearly: requirements, tradeoffs, documentation, and postmortems.

## Year 1: From “zero” to publishing real work

**IS117 (Studio)**

- Outcome: student publishes two sites and learns the vocabulary of products.
- Evidence: portfolio v1 + museum site + terminal/Git/deploy checkoffs.

**IS118 (Proposed, Studio)**

- Outcome: student can build interactive behavior (JS), debug, and integrate an API.
- Evidence: interactive product with verification notes.

## Year 2: From websites to software engineering

**IS218 (Studio)**

- Outcome: student can build a web application as a system (front-end + API + persistence).
- Evidence: deployed app with tests + CI + basic usability evaluation.

**IS219 (Studio)**

- Outcome: student can implement advanced client-side behavior and understands web security/privacy basics.
- Evidence: interactive UI feature set + security hygiene checklist + cross-browser verification.

## Year 3: From building software to building the right software

**IS265 (Studio)**

- Outcome: student learns to frame problems and ask better questions in organizational contexts.
- Evidence: problem framing memo, metrics, and a scoped prototype.

**IS331 (Studio)**

- Outcome: student becomes data-competent (SQL + modeling) and begins modern retrieval concepts.
- Evidence: schema + pipeline + validation + retrieval mini-project.

## Year 4: From systems engineering to enterprise AI engineering

**IS390 (Studio)**

- Outcome: student can produce requirements and designs that engineering teams can implement.
- Evidence: requirements + acceptance tests + design doc + evaluation plan.

**IS425 (Studio)**

- Outcome: student can ship an “AI orchestrator” style system with evaluation, observability, and HITL.
- Evidence: RAG/tool-use workflow (graph/vector where appropriate) + eval harness + runbook + demo-day pitch + postmortem.

## Why this is realistic

- Each semester produces a concrete artifact, not just exams.
- Skills are repeated with higher expectations (terminal, Git, deployment, documentation, evaluation).
- Students learn foundational tools without depending on AI—but also learn to use AI correctly once they can verify.
